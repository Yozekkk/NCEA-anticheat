# Методика тестирования

## Автоматизированные тесты

JUnit 5 запускается через `./gradlew clean build`. `ncea-core` проверяет интервалы движения, границы пяти детекторов, VL, исключения, сессии, права и ASCII-баннер. `ncea-paper` проверяет YAML, диапазоны, отклонение невалидного reload и миграцию старого конфигурационного файла. JaCoCo формирует HTML/XML отчёты в `ncea-core/build/reports/jacoco/test/` и `ncea-paper/build/reports/jacoco/test/`. Проценты приводятся только после чтения отчёта; они не заменяют игровые испытания.

## Локальные серверы

Для каждой версии используется отдельная директория `.integration/` с официальным Paper JAR, сверенным SHA-256, и соответствующим NCEA JAR. Сервер запускается под Java 17, порт привязан к loopback. Сценарий: холодный старт, баннер, `status`, `checks`, `config validate`, валидный `reload`, отклонённый невалидный reload, `stop`, повторный старт. Проверяются логи, коды выхода и отсутствие сообщений `Status: ENABLED` при неудачном старте. Негативный тест конфигурации может закономерно печатать `ERROR`.

## Игровые сценарии до релиза

Подключить локального клиента и отдельно пройти ходьбу, спринт, прыжки, падение, воду, лестницы, плиты, паутину, телепорт, удар/отбрасывание, PvP и быстрые установки блоков. Затем воспроизвести контролируемые аномалии и оценить доказательства, число ложных сигналов и затраты. Результаты не должны объявляться выполненными до фактического прогона. Публичные серверы для разрушительных сценариев не используются.
